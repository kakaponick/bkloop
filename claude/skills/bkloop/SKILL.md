name: bkloop
description: Build a backend goal end-to-end unsupervised in any repo — map the code and the unknowns, spike every unknown against the live system, decompose into tracer bullets, drive each unit red → green through sub-agents, debug what stays red, review, commit unit by unit, assess and rebuild until it converges. Use on /bkloop or when asked for a service, client, worker, queue handler, cron, migration or integration from prompt to commits.
argument-hint: "[N] [jK] <goal>"
---

A system is judged by what it does when run — a test at a seam, a job through the worker, a call against the live system. Agents (`.claude/agents/`): `spike-researcher`, `bkloop-implement`, `bkloop-debug`, `bkloop-critic`. A unit whose work is a user interface belongs to the project's UI loop (`turnkeyloop` or its fork) — recorded as a candidate, not built here.

You own the goal from prompt to committed units, unsupervised: no question reaches the user by any channel (`AskUserQuestion`, `EnterPlanMode`, `socket ask`) — decide, record every judgment call (question / decision / why); the record becomes the report. You launch, read reports by their final block, decide, write briefs, commit messages and the journal — and read no code: a patch, a diff, an output goes into a brief by path. Every command whose output is evidence — a test, a type-check, a build, a migration, a job through the worker, a live or production read, a git command past `status` and `diff` — runs in a launch (`bkloop-run` for a command list; `bkloop-implement`, `bkloop-debug`, `bkloop-critic`, `spike-researcher` per their contracts) because your context is the run's budget and raw output spends it. Sub-agents write code and probe systems — a fresh agent per launch, briefed in full. Nobody in the run edits `CLAUDE.md`, `.claude/` or settings: a law change is an inbox proposal you write.

## Parameters

`/bkloop [N] [jK] <goal>` — `N`, an optional leading integer, caps the passes; omitted → `3`. `jK` caps the lanes open at once; omitted → `j3`; `j1` is serial. Everything after them is the goal. `resume <run id>` as the whole argument → Resume.

**Run id** — minted once: `printf '%s' "$(date -u +%s) <goal>" | git hash-object --stdin | cut -c1-8`; it tags every commit and heads the report, so `git log --grep=<run id>` lists the run.

## Project facts

Before the first launch, read the project's `CLAUDE.md` (and the rule files it names) and its package manifest, and write into `common.md`: install command · type-check · tests (whole repo and one file) · migration generate and apply · how a worker or job runner starts · the default branch (`git symbolic-ref --short refs/remotes/origin/HEAD`, else `CLAUDE.md`) · shared catalogs several units would write (schema, migrations, registries, message catalogs, lockfile) and the catalogue guards — tests that go red when a registry grows (kinds, error types, i18n keys) — with the files they demand · the production-access skill when one exists (`prod`) · the strict rules, verbatim by name · what `.spike/` holds, from its README. A fact the project does not state is a decision, recorded. The commands below are named by role (`<type-check>`, `<tests>`, `<migrate>`); `common.md` holds the real ones.

## Machinery

**Worktree** — the run never edits the checkout it started in. `git worktree add -b bkl/<run id> <repo parent>/bkl/<run id> HEAD`; run the install command in it; copy the starting checkout's untracked env files; `node <start>/.claude/skills/bkloop/spike-lease.mjs link <wt>` — a mirror of `.spike/` (links, nothing to copy back) without `sessions/`: an account's folder appears in a checkout only under its lease (see Sessions); the database per `CLAUDE.md` (a local instance, an in-process one for tests) — additive migrations only, never a reset. Every launch's prompt opens with `Repo: <path>`; tools default to the starting checkout, so pass the path to Glob/Grep and run shell as `cd <path> && …`. **Strays**: `git -C <start> status --porcelain` at every launch and completion; a change there in a file an open unit's manifest names is that unit's stray — diff to a patch in the run folder, apply in the lane, revert in the start checkout, record; a second from the same brief blocks the unit. Any other change is the user's: untouched, listed.

**Lanes** — every unit in flight owns one: `git -C <wt> worktree add -b bkl/<run id>-u<k> <repo parent>/bkl/<run id>-u<k> bkl/<run id>`, install, env and `spike-lease.mjs link <lane>` as above, `common.md` and the brief mirrored into `<lane>/.claude/bkloop/<run id>/`, then `spike-lease.mjs acquire <lane> <session>` for each session the brief names. Open a lane for a ready unit (every unit it is blocked by committed) while fewer than `K` are open and no open unit's manifest shares a path with its manifest. `<wt>` receives only landed units. Close at Land or Block: `spike-lease.mjs unlink <lane>` (releases its sessions), then — only after it printed `unlinked` and `<lane>/.spike` is gone — `git -C <wt> worktree remove --force <lane>`, `git -C <wt> branch -D bkl/<run id>-u<k>`. A removal over a standing mirror walks its junctions and empties the main `.spike/`: a failed unlink is a blocker — move the real folder it names out of the mirror, unlink again; never `rm -rf` / `Remove-Item -Recurse` a checkout.

**Sessions** — an account is a folder `.spike/sessions/<name>/` in the starting checkout (its session string, 2FA, web sessions, notes). One holder at a time, enforced by `spike-lease.mjs`, not by the brief: `acquire` takes an atomic lease and links the folder into the checkout; a checkout without the lease has no such folder at all, so a script, test or worker there fails on a missing path instead of racing — that failure lands under the launch's OPEN and is a decision: acquire when `status` shows it free (`--wait <s>` to queue), relaunch. `release` / `unlink` give it back; the hook `.claude/hooks/spike-guard.mjs` blocks hand-made links, copies of `sessions/` and deleted leases.

**Run folder** — `.claude/bkloop/<run id>/` in the starting checkout: journal, briefs, patches, evidence, report. Not gitignored there → add `.claude/bkloop/` to `.git/info/exclude`.

**Resolve** — a rebase stopped on a conflict is work: a fresh `bkloop-implement` with `Repo:`, the files, both sides' intent (the stopped commit's subject and brief, `git log <default> -3 --format=%s -- <file>`), done-criteria: no markers, `<type-check>` and `<tests>` green, no git command beyond read; then a `bkloop-run` launch: `git add <files>`, `GIT_EDITOR=true git rebase --continue` — stopped again → the next Resolve; up to 5 per rebase, then `--abort` and report. Each resolution is a decision.

**Models** — `bkloop-implement`, `bkloop-debug`, `bkloop-critic` and `spike-researcher` carry `opus` in their frontmatter, `bkloop-run` carries `sonnet`; `Explore` for Map passes `model: sonnet`. A launch on your own model is a spend defect.

**Journal** — two files, so a shell append never lands under the wrong heading: `journal.md`, an append-only decisions table (every decision before the launch that depends on it); `units.md`, the state table (each unit's state `implement · verify · debug · review · fix r<n> · land · committed · blocked`, lane path). Every launch's `description` = `<unit> <role>[ r<round>]` (`u3 implement`, `u3 verify`, `u3 debug`, `u3 critic runtime`, `u3 land`, `spike <topic>`, `assess run`, `integrate`).

**Resume** — `/bkloop resume <run id>`: the run folder is the whole state; a unit found uncommitted in `<wt>` lands there before any lane opens.

## Resources

Autonomy covers code, local state (the worktree, the local database) and everything in `.spike/` — the sessions, proxies, accounts and samples the user put there, described in its `README.md`. Its limits, in the user's words, are the only limits; none written → none. A step that needs something `.spike/` lacks is a decision: the unit builds against the doc, the report says what to drop in. Production is read-only shape, never a target.

## Bar

A finding is **above the bar** when it cites: a done-criterion of the brief · a strict rule of the project's `CLAUDE.md` · a claim in a spike doc the code contradicts · a test rule (a known-answer vector for a parser, codec or crypto path; a test at a seam, not an internal; an expected value from an independent source) · a codebase-design principle with a passed deletion test on a module the unit created or reshaped · an OPEN line of an implementer's or debugger's report. Citing nothing → taste → candidates.

**Declining.** A finding is declined by the user's words, or by you when it contradicts a finding an earlier assessment or review raised (the run does not ping-pong), or when it argues against a settled decision; "pre-existing", "frontend", "later" are never reasons. A declined finding goes to candidates with its why and into the decisions table; it never becomes settled and never counts toward stall.

## Loop

A **pass** is steps 1–4. The first pass builds the goal; each later pass builds only the gap the assessment (step 5) found and starts at step 3 — Map and Spike run again only for an unknown the findings name that no doc covers. Weight earns a pass: critical and major findings above the bar open the next one, minors go to candidates. The run ends when it **converges** (an assessment with no critical or major above the bar), **stalls** (their count, declined excluded, did not fall — or every one of them sits on code the previous pass wrote: fixes of fixes are a stall, and they go to candidates), or after pass `N`.

1. **Map.** One `Explore` (`model: sonnet`) returns tables, no prose: areas the goal touches (files, pattern in use, reference candidate with path — in this repo, else a sibling repo `CLAUDE.md` names as the source); the production shape of every table or queue the goal reads or writes (counts and a typical row through the production skill, read-only; a table production lacks takes its shape from the spec docs against the schema); and the **unknowns** — every external system, protocol, format or behaviour the goal depends on, each with the doc that covers it (`docs/api/*.md`, `docs/research/*.md`, `docs/*.md`, `.spike/toolkits/*/README.md`) and what that doc leaves `unverified`, or `none`. Done when every area has a reference and every unknown a doc or `none`.

2. **Spike.** Every unknown with no doc, or whose doc leaves unverified what a unit will call, gets a `spike-researcher` launch — independent ones in one message, at most `K`, each in `<wt>` after `spike-lease.mjs acquire <wt> <session>` for the sessions it needs (a busy one → that spike waits its turn: `--wait`), released when its report is in; brief per the agent's contract, with what `.spike/` holds and the reference doc = the repo's best findings doc, if any. ANSWERED lines become facts a brief may cite; UNVERIFIED lines become done-criteria where `.spike/` makes them verifiable, otherwise the unit builds on the doc and the report marks it `unverified live`. OPEN lines naming a missing resource → decisions, with what to drop into `.spike/` in the report. Done when every unknown has a doc and every unit-relevant claim is classed live, source or unverified.

3. **Decompose.** Tracer bullets: each unit a vertical slice through every layer it needs (schema and migration, service, handler or cron, action or route, tests), verifiable and committable alone; a prefactor that makes the slices easy is its own first unit, so is a file several slices would write. Each brief `u<k>-brief.md` beside `common.md` (Repo, goal verbatim, project facts, the `.spike/` paths its criteria use, settled decisions):
   - the problem in the user's words and the spike facts it rests on, never the solution;
   - **seams** — the interfaces the tests hit, named (a service function, a handler called directly with a job row, a client method against a fake transport); a test past a seam is a finding;
   - **done-criteria**, every one a command: the first is the red test at the seam (`<tests> <file>`) that must go red before the code and green after; a live criterion names the session (`.spike/sessions/<name>/`) or file it uses and the command, and its test skips itself unless `LIVE=1` and that resource exists — `<tests>` picks every test file up, and only Verify runs it, with `LIVE=1`; a parser, codec or format reader's names its known-answer sample (a real file under `.spike/data/`);
   - file manifest, naming the shared catalogs it may write — a unit that grows a registry names its catalogue guard's files as additive edits, never «not touched»; never `CLAUDE.md`, `.claude/` or settings: a law change the goal implies is an inbox proposal (`.claude/evolve/inbox/`) you write yourself;
   - the reference to match — the best in-repo example of the same kind (a handler for a handler, a client for a client);
   - settled decisions — the user's words, interfaces committed units expose, spike facts — each with why.

   Track units in the task list. Done when every unit carries all six parts.

4. **Units, in lanes.** At pass start, no lane open: `git -C <wt> rebase <default>` on the run branch — a conflict → Resolve. Launch every newly opened lane's implement in one message; on each completion advance that unit alone, then open lanes again.
   - **Implement.** `bkloop-implement` with `Repo: <lane>` and the brief's path. Its report carries RED (the seam test's failing run, verbatim line) before GREEN; CREATED extends the manifest.
   - **Verify.** One `bkloop-run` launch in the lane with the list and each command's expected outcome: the RED command (green now); `<type-check>`; `<tests>`; every other done-criterion command, live ones under `LIVE=1`; schema changed → `<migrate-generate>` and `ls` of the migration file. Red → its log path, the red line verbatim, the brief path and `git diff` of the unit's files (a patch in the run folder) to a fresh `bkloop-implement`, once. Still red → `bkloop-debug` with the exact red command, the brief path and the diff; it applies its own FIX, its LOOP command joins the done-criteria. Up to two debug launches per unit; then Block. A live criterion blocked by a missing resource is a decision, the gate falls back to the offline criteria, the report says `unverified live`.
   - **Review.** `bkloop-critic` with `LENS: code` and `LENS: runtime`, one launch each in one message: brief path, file list, settled decisions, the spike docs the unit rests on, the implementer's RED/GREEN lines. Merge, rank, judge against the bar; a finding re-litigating a settled decision is dropped. Review runs once per unit; after a fix round the critics are relaunched only with the fix round's list and answer closed / open per item — a new finding there joins the next round at critical or major above the bar (within the round cap), a minor is a candidate.
   - **Fix round.** Critical and major findings above the bar verbatim to a fresh `bkloop-implement` → Verify; minors → candidates. The manifest does not grow in a fix round: a fix that needs a new file is a candidate. At most two rounds per unit (`r2`); a critical or major still open after that → Block.
   - **Land.** One lane at a time. Write the commit message to the run folder (the trailer `bkloop: <run id> pass <p>/<N> unit <k>/<total> rounds <r>`; the project's commit conventions (`CLAUDE.md`) apply), then one `bkloop-run` launch: `git status --porcelain` — a dirty file the unit did not touch is a stray, `git diff -- <file>` to a patch in the run folder, `git checkout -- <file>`; `git add` by explicit path; `git commit -F <message>`; `git rebase bkl/<run id>` — a conflict stops the launch → Resolve; base moved → `<type-check>`, `<tests>`, schema changed → `<migrate-apply>`, build-exercised code changed → the build. Red → fix round, then a launch for `git commit --amend --no-edit` and the checks again. Green → `git -C <wt> merge --ff-only bkl/<run id>-u<k>`, close the lane.
   - **Block.** Save `git -C <lane> diff` of the unit's files as a patch, record the exact state, close the lane. Units blocked by this one are blocked too, with the reason.

5. **Assess.** Every unit committed or blocked → `bkloop-critic` with `LENS: code` and `LENS: runtime` in assessment mode on everything the goal touched — briefed with the goal verbatim, the spike docs, the production shape, the full file list; no brief, no settled decisions — and the **end-to-end run**: the goal's scenario executed for real in the worktree by a `bkloop-run` launch briefed with the scenario as commands and expected transitions — a job enqueued through the service and taken by the worker against the local database, the row's transitions read back; a cron's `run` called directly; a step against the live system with `.spike/` where it allows goes to a `spike-researcher` with the toolkit (sessions acquired for `<wt>` for the run's duration, released after — no lane is open at Assess). Each launch's COMMANDS lines become the evidence table (command / outcome); a step nothing in `.spike/` covers is a decision. Judge by the bar; a finding against a settled decision is declined (see Declining); a finding on what no pass built is a candidate. Decide: converged · stalled · next pass (back to step 3 with the findings as the goal) · cap.

6. **Integrate.** A `bkloop-run` launch per stage, the git commands as listed here and nothing beyond them. Rebase: `git fetch origin`; `git rebase <default>` on the run branch — conflict → Resolve; when the paths both sides changed (`comm -12`) would stop it past the Resolve cap, `git merge <default>` into the run branch instead — one Resolve on final states, a merge commit on top, `<default>` still fast-forwards. Clean → fast-forward `<default>` with no hand on it: the starting checkout on `<default>` → `git -C <start> stash push -u` when dirty, `git -C <start> merge --ff-only bkl/<run id>`, `git -C <start> stash pop` (a pop conflict → the stash stays, its name reported); on another branch → `git -C <wt> push . bkl/<run id>:<default>`. Push: its own launch, briefed with the `git log origin/<default>..<default>` list you approved (what goes, foreign commits named) — `git -C <start> push origin <default>`; rejected → `pull --rebase --autostash` once (Resolve on conflict), push again; rejected again → reported verbatim, never forced. Success → `spike-lease.mjs unlink <wt>` (yours), then `git worktree remove <wt>` (as for a lane: only after `unlinked`), `git branch -d bkl/<run id>`; either way `spike-lease.mjs status` must show every session free before Finish.

7. **Finish** — in the user's language. **Report file** `report-<date>-<slug>.md` in the run folder, run id first, then tables only: decisions · project facts · spikes (question / doc / answered / unverified / what `.spike/` lacked) · units (pass / unit / red → green / findings above the bar / open after fix / verdict / sha or patch) · evidence (criterion / command / outcome, `unverified live` marked) · assessments (pass / critical+major / minors to candidates / outcome) · candidates · spend, the verbatim output of `node <start>/.claude/skills/bkloop/spend.mjs <session id>`. **Chat summary**: verdict first — goal met, converged / stalled / cap at which pass; what was built; what runs for real and what is `unverified live`; commit table; integration result; spend; not done; what to drop into `.spike/`; the report as a link.
